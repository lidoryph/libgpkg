# Security Policy

**This file is subject to change, always check it before submitting a vulnerability.**

## Reporting a Vulnerability

You must report vulnerabilities through GitHub's "Security" page or through an encrypted email to the leaders of the project.

> Always report vulnerabilities through GitHub unless you can't use it.

## Dos & Don'ts

- DO NOT open public issues for security vulnerabilities.
- DO NOT open public pull requests for security vulnerabilities.
- DO NOT open public discussions for security vulnerabilities.
- DO NOT disclose the vulnerability publicly until there's a fix available.
- DO NOT include issues coming from third party dependencies.
- DO NOT report bad quality AI vulnerabilities.


- Report issues through the channels mentioned above.
- Disclose if an AI was used to find the vulnerability.

## What to include

Include a description of the issue, reproduction steps, or proof of concept. 
Also include the potential impact of the issue.

A CWE should be specified if it applies, and a CVE will be automatically assigned through GitHub when the advisory is published.

## Safe Harbour and Credit

We won't pursue legal action against anyone who reports in good faith and
follows this policy. Reporters will be credited in the advisory unless they
prefer to stay anonymous.
